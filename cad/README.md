# CAD and simulation

Everything here is generated from `analysis/results.json` and `cad/hardware.json`. After changing the sizing or the hardware spec, re-run the build and the CAD follows. Nothing is modelled by hand.

## Files

| File | Purpose |
|---|---|
| `params.mjs` | Converts the sizing results and `hardware.json` into build parameters, fastener definitions, the fastener schedule, every component placement (position + rotation matrix) and the exploded layout → `params.txt` |
| `hardware.json` | Machine-readable twin of `docs/research/hardware-spec.md`: fasteners, nuts, washers, inserts, fits, general tolerances (same IDs as the spec and the drawings) |
| `BuildVtol.cs` | SOLIDWORKS API builder: 75 unique part files (`verification.txt` 2026-11-01), the 397-component `VTOL_Concept.SLDASM` (STEP, EASM), `VTOL_Exploded.SLDASM`, interference detection and mass roll-up → `verification.txt` |
| `build.ps1` | Runs `params.mjs`, then compiles and runs the builder, mesh export, drawings and renders (needs SOLIDWORKS 2025 + .NET Framework 4 `csc`) |
| `Drawings.cs` | Builds drawing DBF-DRW-001 rev G (nine ANSI B sheets, see below) with driven dimensions, tolerances and fits from `params.txt` (note text included: every size that follows the sizing is read from `params.txt`); zoned layout with a self-check of overlaps (`drawings/layout-check.txt`); exports `.SLDDRW`, a vector PDF and sheet PNGs to `drawings/`. `Drawings.exe model drawings params.txt 2,3` builds only the listed sheets as `probe_*` files for layout iteration |
| `Shared.cs` | Compiled into `BuildVtol.exe`, `Drawings.exe`, `Sim.exe` and `Thermal.exe`: `ParamsFile`, the one C# reader of `params.txt`, and `Geom`, the one C# implementation of the NACA 4-digit section and the pod profile (constants read back from `params.txt`, see "Single sources" below) |
| `SharedTest.cs` | Parity test of `Shared.cs` against the inline code it replaced (bit-exact sections, pod radii and parsed parameters; no SOLIDWORKS). `build.ps1` compiles and runs it before every build; by hand: `csc /nologo /out:%TEMP%\SharedTest.exe cad\Shared.cs cad\SharedTest.cs && %TEMP%\SharedTest.exe cad\params.txt` |
| `ExportMesh.cs` | Exports each part as a binary STL (metres, part frame) plus colour and description → `mesh/`; `review/mesh.mjs` packs them (one pre-rotated mesh per part orientation) for the interactive viewer in the review page |
| `Snap.cs` | Saves iso/top/side/front PNGs of the assembly → `images/` |
| `BuildFigs.cs` | Step figures for the build manual: per figure in `docs/build/figs.txt`, shows the parts a step fits (orange, with their fasteners in blue) among the parts already built, renders and crops → `docs/build/img/*.jpg` (assembly closed unsaved) |
| `Sim.cs` | SOLIDWORKS Simulation studies → `sim/results.txt`, plots, and `sim/*.SLDPRT` with the studies saved inside (re-run 2026-11-02 on the 2026-11-01 sizing, see below) |
| `ListDocs.cs` | Lists open SOLIDWORKS documents; `ListDocs.exe close` closes files under this folder, `close untitled` also discards unsaved new documents |
| `Inspect.cs` | Lists a part's feature tree, bodies, volume and box (debugging aid) |
| `TlbImp.cs`, `Probe.cs` | Tools used to inspect the Flow Simulation API and add-in availability |
| `model/` | Generated parts, `VTOL_Concept.SLDASM`, `.STEP`, `.EASM`, `VTOL_Exploded.SLDASM` |
| `verification.txt` | Interference report, component counts, cosmetic-thread count, mass roll-up (generated by each build) |

## Fastener modelling

Each instance is placed at its joint by a rigid transform (rows of the 3 × 3 matrix in the `comp=` line are the images of the part axes), with holes in the parent parts at the spec's clearance/insert diameters (printed model value = ISO 273 normal + 0.2). Cosmetic threads (InsertCosmeticThread3) are on the shank of every screw, the bores of the nuts and the insert and the M6 adapter (17 of the 18 fastener part files; the washer has none). ## Single sources (code review 2026-10-25, "one geometry described in several places")

The wing/tail section family and the fuselage-pod profile used to be re-typed in six places (two different trailing-edge coefficients, `cad/params.mjs`, `BuildVtol.cs`, `Drawings.cs`, `analysis/aero/common.py`, `docs/build/templates/make_templates.py`) and `params.txt` was parsed by six different readers. They are now defined once and read through one module per language; the refactor changed no output (all regenerated outputs byte-identical, see `SharedTest.cs` and the parity notes in `analysis/README.md`).

| What | Single source | Readers |
|---|---|---|
| Section family: NACA 24xx camber (`m` 0.02, `p` 0.4; `t` = sizing `tc`), NACA 0009 tail, TE coefficients `teCad` −0.1015 / `teAero` −0.1036, pod profile (`noseX` 0.6, `L` 1.0, `R` 0.08, `tailR` 0.03, `noseA` 0.22, `parallelTo` 0.65; `params.txt` podProfile, fusL) and the reference formulas | `analysis/geometry.mjs` (a leaf module: imported by `analysis/sizing.mjs`, `analysis/tradestudy.mjs` and `cad/params.mjs`; the sizing never reads `params.txt`, which is generated from it) | — |
| The same constants as data | `params.txt` keys `foilWing`, `foilTail`, `foilTE`, `podProfile` (text records `label\|name=value...`, written by `params.mjs`; `fusL`, `fusR`, `tailR`, `tc` stay numeric keys) | `analysis/geom.py` (Python: `read_params`, `naca4_surfaces`/`naca4_outline`, `pod_radius`; used by `analysis/aero/common.py` and so every aero script, and by `make_templates.py`), `cad/Shared.cs` (C#: `ParamsFile.Load`, `Geom.WingSection`/`TailSection`/`Naca`/`NacaYt`/`NacaYc`/`PodRadius`; used by `BuildVtol.cs`, `Drawings.cs`, `Sim.cs`, `Thermal.cs`) |
| `params.txt` parsing rules | documented in `analysis/geom.py` and `cad/Shared.cs` (trim; blank lines ignored; a line without `=` or a repeated key is an error; `comp=`/`xcomp=` are records, everything else a scalar) | the two readers above; `review/build.mjs` keeps its own numeric-only reader and skips the text records |

**Trailing edge.** Two coefficients remain in use on purpose: the CAD, drawings and `params.txt` stations use the original open-TE polynomial (−0.1015, TE thickness 0.0021 c = 0.7 mm at the 322.3 mm chord *(calc)* — the better model of a hot-wired XPS core with a tape skin), while the aero package (SU2 meshes, NeuralFoil) and the hot-wire templates use the closed-TE value (−0.1036; a closed contour for meshing and a clean wire exit). Forward of 70 % chord the two differ by < 0.05 mm. Unifying them would change either the CAD coordinates or the aero/template outputs, so both are named at the single source (`FOIL.teCad`, `FOIL.teAero`) and the choice per consumer is explicit. Recommendation for the next template revision: move `make_templates.py` onto `teCad` so the templates match the drawn section (changes the SVG/CSV by ≤ 0.7 mm at the TE only).

`Sim.cs` and `Thermal.cs` are built by hand with `Shared.cs` on the command line, e.g. `csc /nologo /platform:x64 /out:cad\Sim.exe /r:"<redist>\SolidWorks.Interop.sldworks.dll" /r:"<redist>\SolidWorks.Interop.swconst.dll" /r:cad\SolidWorks.Interop.cosworks.dll cad\Sim.cs cad\Shared.cs`.
